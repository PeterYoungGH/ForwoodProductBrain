# Experiment Readiness Checklist

**Purpose:** Verify an experiment is ready to be executed, ensuring it is well-designed and properly resourced.

## Pre-Readiness Checks

Before assessing experiment readiness, verify the experiment meets basic quality standards:

### Format Validation
- [ ] Experiment follows required structure per `04-opportunities/05-experiments/RULES.md`
- [ ] Title uses format: `# Experiment: [Name]`
- [ ] All required metadata fields are present (Status, Created, Last Updated)
- [ ] Overview clearly describes what is being tested

### Solution Linking
- [ ] Links to exactly one solution
- [ ] Link uses correct relative path
- [ ] Experiment clearly tests the linked solution

### Hypothesis
- [ ] Hypothesis is clear and testable
- [ ] Hypothesis is falsifiable
- [ ] Hypothesis includes expected outcome and success criteria

## Readiness Criteria

An experiment is ready for execution when:

### 1. Solution Readiness
- [ ] Solution is well-defined
- [ ] Assumptions are documented
- [ ] Solution addresses a validated opportunity

### 2. Experiment Design
- [ ] Experiment design is validated
- [ ] Hypothesis is clear and testable
- [ ] Success criteria are defined and measurable
- [ ] Methodology is detailed and specific

### 3. Resource Availability
- [ ] Resources are available to run experiment
- [ ] Timeline is acceptable
- [ ] Dependencies are resolved

### 4. Stakeholder Alignment
- [ ] Key stakeholders are aligned
- [ ] Approval obtained if required
- [ ] Communication plan in place

## Experiment Design Validation

### Hypothesis Quality
- [ ] Hypothesis is clear and specific
- [ ] Hypothesis is testable
- [ ] Hypothesis is falsifiable
- [ ] Hypothesis links to assumption being tested

### Success Criteria
- [ ] Primary success criteria defined
- [ ] Success criteria are measurable
- [ ] Criteria align with assumption
- [ ] Thresholds are set

### Methodology
- [ ] Experiment type is appropriate
- [ ] Methodology is detailed
- [ ] Participant/data selection criteria defined
- [ ] Bias and confounding factors considered

### Resource Requirements
- [ ] Time estimate is reasonable
- [ ] People/resources identified
- [ ] Tools/equipment available
- [ ] Dependencies resolved

## Readiness Assessment

**Ready for Execution:**
- [ ] All pre-readiness checks passed
- [ ] All readiness criteria met
- [ ] Experiment design validated
- [ ] Resources available
- [ ] Stakeholders aligned

**Not Ready - Missing Requirements:**
- [ ] List missing requirements
- [ ] Identify what needs to be completed
- [ ] Suggest next steps

## Decision Logging

When readiness is assessed:
- [ ] Decision log entry created (if significant assessment)
- [ ] Assessment date recorded
- [ ] Rationale documented
