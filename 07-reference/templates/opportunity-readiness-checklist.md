# Opportunity Readiness Checklist

**Purpose:** Verify an opportunity is ready for solution exploration.

## Pre-Readiness Validation

Before assessing solution readiness, verify the opportunity meets basic quality standards:

### Format Validation
- [ ] Opportunity follows required structure per `04-opportunities/03-opportunities/RULES.md`
- [ ] Title uses format: `# Opportunity: [Name]`
- [ ] All required metadata fields are present (Status, Created, Last Updated, Priority)
- [ ] Overview is clear and customer-focused

### Content Quality
- [ ] Customer Problem section describes customer needs (not solutions)
- [ ] No solution language in problem description
- [ ] Problem is specific and actionable
- [ ] Document is customer-focused throughout

### Evidence Requirements
- [ ] At least one piece of evidence is provided
- [ ] Evidence is specific and credible
- [ ] Evidence links are correct and working
- [ ] Evidence supports the opportunity

### Outcome Linking
- [ ] Links to at least one product outcome
- [ ] Links use correct relative paths
- [ ] Connection to outcome is clear
- [ ] Opportunity description explains impact on outcome

## Solution Readiness Criteria

An opportunity is ready for solution exploration when:

### 1. Opportunity Quality
- [ ] Opportunity is well-formed and customer-focused
- [ ] Problem statement is clear
- [ ] Strong evidence supports the opportunity

### 2. Outcome Linking
- [ ] Links to valid product outcome
- [ ] Connection is clear and explicit

### 3. Prioritization
- [ ] Opportunity is Active (not Backlog)
- [ ] Has sufficient priority to warrant solution exploration
- [ ] Prioritization decision has been logged

### 4. Research Completeness
- [ ] Sufficient research to understand the problem
- [ ] Customer needs are well-understood
- [ ] No major unknowns that would block solution design

## Readiness Assessment

**Ready for Solution Exploration:**
- [ ] All pre-readiness validation items checked
- [ ] All solution readiness criteria met
- [ ] No blocking issues identified

**Not Ready - Missing Requirements:**
- [ ] List missing requirements
- [ ] Identify what needs to be completed
- [ ] Suggest next steps

## Decision Logging

When readiness is assessed:
- [ ] Decision log entry created (if significant assessment)
- [ ] Assessment date recorded
- [ ] Rationale documented
