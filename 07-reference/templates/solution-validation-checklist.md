# Solution Validation Checklist

**Purpose:** Verify a solution is ready for experimentation and validate it addresses the opportunity effectively.

## Pre-Validation Checks

Before validating a solution, verify it meets basic quality standards:

### Format Validation
- [ ] Solution follows required structure per `04-opportunities/04-solutions/RULES.md`
- [ ] Title uses format: `# Solution: [Name]`
- [ ] All required metadata fields are present (Status, Created, Last Updated, Priority)
- [ ] Overview clearly describes solution and connection to opportunity

### Opportunity Linking
- [ ] Links to exactly one opportunity
- [ ] Link uses correct relative path
- [ ] Solution clearly addresses the linked opportunity

### Solution Description
- [ ] Solution Description section is detailed and clear
- [ ] "How It Addresses the Opportunity" section explains the connection
- [ ] Solution is specific and actionable

## Validation Criteria

A solution is validated when:

### 1. Solution Quality
- [ ] Solution clearly addresses the opportunity
- [ ] Connection to opportunity is explicit
- [ ] Solution is well-defined

### 2. Risk Assessment
- [ ] Four product risks have been assessed
- [ ] Risk levels documented (High/Medium/Low for each)
- [ ] High-risk areas identified
- [ ] Mitigation strategies documented

### 3. Assumptions Documentation
- [ ] Key assumptions are documented
- [ ] Assumptions are testable
- [ ] Assumptions map to risks

### 4. Validation Planning
- [ ] Validation plan exists or can be created
- [ ] Experiments suggested for high-risk assumptions
- [ ] Experiment sequence proposed

### 5. Implementation Considerations
- [ ] Effort assessed (High/Medium/Low)
- [ ] Complexity assessed (High/Medium/Low)
- [ ] Dependencies identified
- [ ] Risks identified

## Risk Assessment Validation

### Value Risk
- [ ] Assessed: [High / Medium / Low]
- [ ] Evidence reviewed
- [ ] Missing evidence identified

### Usability Risk
- [ ] Assessed: [High / Medium / Low]
- [ ] Evidence reviewed
- [ ] Missing evidence identified

### Feasibility Risk
- [ ] Assessed: [High / Medium / Low]
- [ ] Evidence reviewed
- [ ] Missing evidence identified

### Business Viability Risk
- [ ] Assessed: [High / Medium / Low]
- [ ] Evidence reviewed
- [ ] Missing evidence identified

## Validation Assessment

**Solution Validated:**
- [ ] All pre-validation checks passed
- [ ] All validation criteria met
- [ ] Risk assessment complete
- [ ] Validation plan approved

**Not Validated - Issues:**
- [ ] List validation issues
- [ ] Identify what needs to be addressed
- [ ] Suggest next steps

## Decision Logging

When solution is validated or selected:
- [ ] Decision log entry created
- [ ] Risk assessment logged (especially high-risk areas)
- [ ] Validation plan approval logged (if applicable)
