# Opportunity: Customers Want to Extend Existing Platform to Support Security Incident Management

**Status:** Active  
**Created:** 2025-12-01  
**Last Updated:** 2025-12-01  
**Priority:** Medium

## Overview

Customers using Forwood for EHS (Environmental, Health, and Safety) management want to extend their existing platform to also support Security incident management and investigations, avoiding the need to implement and maintain separate systems.

## Customer Problem

Organizations like Kenmare are managing Security incidents and investigations separately from their EHS operations, requiring them to maintain multiple systems and workflows. This creates several challenges:

- **System Proliferation**: Organizations must implement and maintain separate systems for EHS and Security incident management, increasing complexity and cost
- **Data Fragmentation**: Security and EHS data exist in silos, making it difficult to get a unified view of organizational risk and incidents
- **Workflow Inefficiency**: Teams must switch between systems and duplicate data entry, reducing operational efficiency
- **Inconsistent Reporting**: Security and EHS teams use different tools, making it challenging to create unified dashboards and reports
- **Limited Value Realization**: Customers want to maximize value from their existing Forwood investment by extending it to additional use cases

Kenmare specifically wants to understand if their existing Forwood platform can be configured to support Security incident management using the same base data structure (sites, locations, departments, employees) already available for EHS. They need to manage Security incidents as a separate module while maintaining appropriate access controls between EHS and Security teams, and they want Security-specific dashboards and heat maps similar to what they have for EHS.

The core customer need is to avoid implementing a new system and instead extend what they already have, maximizing value from their current Forwood investment while reducing system complexity and operational overhead.
